# 工业纪元

以现实电力和工业机制为基础的 Mindustry 模组。当前版本先提供电网运行、分区供电、工程输电、保护、储能与黑启动；煤炉、蒸汽、工业生产、科技树和自有战役将在后续逐步扩展。

## 当前版本

**0.5 测试版**，本次构建为 `flow-20261014-publish`，使用 Mindustry v8 Build 160.5 和 JDK 17 编译验证。其他引擎版本及移动平台尚未验证。

玩家显示名称由“现实电力系统”改为“工业纪元”。内部标识继续使用 `blackstart`，本次更名保持已有建筑标识与存档格式。

## 下载与安装

下载 [industrial-epoch-0.5-test.jar](downloads/industrial-epoch-0.5-test.jar)，在游戏模组管理中导入，或在保存并退出游戏后放入模组目录，再启动游戏。

更新已有版本时替换旧包，保留一份备份；不要同时安装两个内部标识为 `blackstart` 的包。Steam 桌面版的模组目录通常位于 `<游戏安装目录>/saves/mods/`。

多人游戏各端必须使用同一构建的包；仅版本号同为0.5不足以判断一致。完整文件指纹见 [SHA256SUMS.txt](downloads/SHA256SUMS.txt)。

## 现在能玩到什么

- 普通、高压和特高压工程输电，跨分区供电与逐跳损耗。
- 多个电源同时供电，以及工程节点多级中转；中转先满足本地负载，再转送电力。
- 逐条出线的手动输送上限，与保护限流独立。
- 原版电力节点的分区管理、逐线分合及影响预览。
- 14类原版发电设备的分型适配，机组启动和动态响应。
- 跟网/构网储能、频率动态、保护与黑启动恢复。
- 电网覆盖层、可调悬浮字号、事件记录和黑启动演习。
- 完整存档中的机组、调节与保护状态续接，减少切图后无条件重置带来的停电。

工程线路仍是有向输送关系；可连接多条线不意味着无需求时所有线路都会有流量。实际供电受电源余量、负载需求、容量、损耗和保护限制。当前模型没有交流电压或无功潮流求解。

### 如何调节工程线路

打开模组“设置”，在悬浮字号下方进入“工程流量”，选择本队工程节点。每条出线可以单独设置0–100%的额定输送上限，默认100%，拖动后点击该线路“应用”。

0%保留连接并将输送上限降为零；100%恢复额定上限。入线在源端设置。上限不是强制流量，不会凭空增加发电或令空闲线路耗电。设置随当前世界保存，拆线或端点重建后旧设定失效；房主可修改，客户端只读。

## 本次更新

修复标准融合模式的小流量持续欠供与中转需求不向上游传递的问题，加入逐线限流，并改善分支、环路、备用路径和暂停保存边界。包含工程节点、断路器及两类储能的四张新贴图，并修复无效运输条目含空电网引用时可能崩溃的问题。兼容模式沿用既有控制行为，手动限流仍生效。

最新美工与崩溃修复基线的自动回归为320项通过、0项失败，涵盖无头电网、存档、遥测及Scene2D交互；本次更名构建另核对代码、贴图一致性与包内容。构建验证使用160.5，引发这次崩溃的160.7环境修复效果仍需真实试玩确认；其他真实双端网络时序与大图性能也待验。

## 从源码构建

需要JDK 17和Mindustry Build 160.5桌面jar。游戏本体和JDK不随仓库分发。固定参考引擎的MD5为 `f3a66564b1fbf45a1c0e50d7499c2283`。

Windows PowerShell：

```powershell
./build.ps1 -Jdk 'C:/path/to/jdk17' -Engine 'C:/path/to/desktop.jar'
```

或使用JDK的Java源码启动器：

```text
java tools/Build.java /path/to/desktop.jar
```

构建输出为 `dist/blackstart-0.5-test.jar`；这是沿用内部标识的文件名，包内玩家名称为“工业纪元”。`build.sh`和Gradle保留为备用构建方式，输出位置不同。

仓库包含运行源码、必要资源、构建工具、可安装包及玩家规划；测试存档、本机工具链、内部任务书和施工台账不随本次更新分发。
